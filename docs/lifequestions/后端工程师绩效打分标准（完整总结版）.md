# 后端工程师绩效打分标准（完整总结版）

> 📌 **核心原则**：不评价"他是什么样的人"，只评价"他做出了什么可观测的行为结果"

---

## 一、公式总览

```
最终绩效分 = 
    [ L5_行为表现层 × 任务复杂度系数C ] × 50% 
  + L4_情绪行为层 × 20% 
  + L3_协作贡献层 × 15% 
  + L2_方案质量层 × 10% 
  + L1_成长自驱层 × 5%
  + 加分项 B₊ - 扣分项 B₋
  ─────────────────────────────
  结果约束：MAX(0, MIN(120, 计算结果))
```

| 符号 | 含义 | 范围 |
|-----|------|------|
| L1~L5 | 各层得分（1-10分制） | 1~10 |
| C | 任务复杂度系数 | 0.9 / 1.0 / 1.1 |
| B₊/B₋ | 加分/扣分项 | B₊≤20, B₋≥0 |
| 最终绩效分 | 映射后总分 | 0~120 |

---

## 二、各层得分计算规则（1-10分制·主管直评）

### 🔹 L5_行为表现层（权重50%）
```
L5 = (代码质量×0.4 + 交付效率×0.3 + 系统稳定×0.2 + 技术习惯×0.1) × C
```

| 子项 | 权重 | 参考数据 | 10分标准 | 6-7分标准 | 1-3分标准 |
|-----|------|---------|---------|----------|----------|
| **代码质量** | 40% | 千行Bug数、CR驳回率 | Bug≤0.3 + CR≤5% | Bug 0.8-1.8 + CR 12-25% | Bug>3.5 + CR>45% |
| **交付效率** | 30% | 准时交付率 | ≥98% | 80-90% | <60% |
| **系统稳定** | 20% | SLA、P0/P1故障 | SLA≥99.9% + 零故障 | SLA 95-99% + P1≤1 | SLA<95% + P0≥1 |
| **技术习惯** | 10% | 文档/注释/Git规范 | ≥95% + 100%规范 | 75-85% + ≥80%规范 | <55% + <50%规范 |

> 📏 评分规则：代码质量取「Bug分」与「CR分」的**较低分**（木桶原则）

---

### 🔹 任务复杂度系数 C（仅校准L5）

| 等级 | 系数 | 适用场景 | 确认时机 |
|-----|------|---------|---------|
| 困难 | ×1.1 | 核心模块/高并发/新技术探索 | 周期初主管+员工共同确认 |
| 标准 | ×1.0 | 常规需求/功能迭代 | - |
| 简单 | ×0.9 | 简单CRUD/维护性任务 | - |

> ✅ C只乘L5，因为任务难度直接影响产出结果，不影响能力/特质类指标（L1-L4）

---

### 🔹 L4_情绪行为层（权重20%）
```
L4 = 故障响应×0.5 + 沟通专业×0.3 + 协作反馈×0.2
```

| 子项 | 参考数据 | 10分标准 | 6-7分标准 | 1-3分标准 |
|-----|---------|---------|----------|----------|
| **故障响应** | MTTA、on-call记录 | ≤5分钟+主动跟进 | 10-20分钟+按时处理 | >30分钟或需多次催促 |
| **沟通专业** | 360度反馈、冲突记录 | 压力场景保持专业+主动同步 | 偶有情绪但不影响协作 | 情绪化沟通+引发冲突 |
| **协作反馈** | CR采纳数、求助响应 | 评论高质量+被采纳≥80% | 评论有用+被采纳50-80% | 很少评论或评论无价值 |

---

### 🔹 L3_协作贡献层（权重15%）
```
L3 = 协作贡献×0.4 + 知识沉淀×0.4 + 团队融合×0.2
```

| 子项 | 参考数据 | 10分标准 | 6-7分标准 | 1-3分标准 |
|-----|---------|---------|----------|----------|
| **协作贡献** | CR评论数/质量、跨组支持 | 主动输出高质量建议+被广泛采纳 | 按需参与+评论有价值 | 很少参与或评论敷衍 |
| **知识沉淀** | Wiki数、分享次数、新人指导 | 文档系统+分享≥2次/季+带新人 | 有文档+偶尔分享 | 很少沉淀或内容质量低 |
| **团队融合** | NPS评分、会议参与、活动投入 | 主动促进协作+团队认可度高 | 配合度好+无明显冲突 | 协作被动或引发摩擦 |

---

### 🔹 L2_方案质量层（权重10%）
```
L2 = 方案深度×0.5 + 复盘质量×0.3 + 技术创新×0.2
```

| 子项 | 参考数据 | 10分标准 | 6-7分标准 | 1-3分标准 |
|-----|---------|---------|----------|----------|
| **方案深度** | 技术评审记录、返工次数 | 一次性通过+考虑边界/容灾/扩展 | 1-2轮修改+逻辑清晰 | ≥3轮修改或有重大缺陷 |
| **复盘质量** | 故障复盘报告、措施落地 | 根因深入+措施100%落地+分享 | 有分析+措施部分落地 | 流于形式或无改进动作 |
| **技术创新** | 新技术引入、效能提升数据 | 引入新技术+带来≥20%效能提升 | 有优化尝试+有小幅提升 | 无创新或尝试失败无沉淀 |

---

### 🔹 L1_成长自驱层（权重5%）
```
L1 = 自驱行为×0.6 + 价值观匹配×0.4
```

| 子项 | 参考数据 | 10分标准 | 6-7分标准 | 1-3分标准 |
|-----|---------|---------|----------|----------|
| **自驱行为** | 主动任务数、学习记录、技术提案 | 主动承担难点+有成长规划+输出成果 | 按需完成任务+有学习计划 | 被动等待安排+无成长动作 |
| **价值观匹配** | 代码规范、数据合规、协作诚信 | 完全符合+有正向影响 | 基本符合+无违规记录 | **触碰红线=0分且总评D级** |

> ⚠️ 价值观匹配采用**一票否决制**：数据造假/恶意代码/泄露等红线行为，直接D级

---

## 三、加减分项规则

### ✅ 加分项 B₊（上限+20分）

| 类型 | 条件 | 加分 | 验证方式 |
|-----|------|------|---------|
| 技术创新 | 引入新技术带来≥20%效能提升 | +10~15 | 数据报告+技术委员会评审 |
| 知识分享 | 内部分享获≥80%好评 | +3~8 | 匿名反馈+分享材料 |
| 紧急救火 | 非on-call时段解决P0故障 | +2~5/次 | 故障报告+值班记录 |
| 人才培养 | 指导新人独立承担模块 | +3~6/人 | 新人评估+主管确认 |

### ❌ 扣分项 B₋（无下限，总分≥0）

| 类型 | 条件 | 扣分 | 说明 |
|-----|------|------|------|
| 重大事故 | 因个人疏忽导致P0故障 | -10~-30 | 根据影响时长/损失定级 |
| 重复犯错 | 同类问题重复发生≥3次 | -5/次 | 需有复盘记录证明 |
| 协作障碍 | 360度协作评分持续<60分 | -3~-10 | 需有具体行为证据 |
| 价值观红线 | 数据造假/恶意代码/泄露 | -100 | 直接总评D级，进入PIP |

## 四、绩效评级映射

```
IF 最终绩效分 ≥ 105 → S（卓越）：超越预期，标杆水平
IF 90 ≤ 最终绩效分 < 105 → A（优秀）：完全达标，稳定输出
IF 75 ≤ 最终绩效分 < 90 → B（良好）：基本达标，有改进空间
IF 60 ≤ 最终绩效分 < 75 → C（待改进）：部分达标，需重点辅导
IF 最终绩效分 < 60 → D（不合格）：未达标，需干预或调整
```

---

## 五、公平性保障机制

### 🔒 1. 数据可溯源
- 所有输入指标需关联Git/Jira/监控系统记录
- 主观评分需有行为锚定依据（BARS）

### 🔒 2. 极端值处理
- 360度评分自动剔除±10%极端值
- 评分人数<5人时，不启用360度，仅用主管+系统数据

### 🔒 3. 情境豁免
```
IF 员工申报特殊情境（生病/家庭变故等）AND 审批通过:
    L4/L1权重减半，释放权重转给L5
    → 该周期更聚焦可观测产出，减少状态波动影响
```

### 🔒 4. 申诉通道
- 员工可对任意子项发起复核
- 复核需基于原始数据（Git/Jira/监控日志）
- 复核结果覆盖原值，为最终结果

## 六、实施检查清单

### ✅ 评分前
- [ ] 任务复杂度系数C已在周期初确认
- [ ] 所有参考数据已同步（Git/Jira/监控）
- [ ] 360度评分已收集并完成极端值处理
- [ ] 价值观红线已明确告知员工

### ✅ 评分中
- [ ] 各子项按1-10分直评，有行为依据
- [ ] L5的复杂度系数C只乘L5，不参与其他层
- [ ] 加权权重正确：L5=50%, L4=20%, L3=15%, L2=10%, L1=5%
- [ ] 加权结果×10映射到0-100分

### ✅ 评分后
- [ ] 输出各层得分明细，便于反馈改进
- [ ] 附复杂度系数说明和360度评分分布
- [ ] 提供改进建议（聚焦L2/L5可行动项）
- [ ] 告知申诉通道和复核流程

## 七、一句话总结

> 🎯 **公式核心**：  
> 「层内加权→层间加权→×10映射」，复杂度系数C只校准L5硬性产出  
>  
> 📏 **公平核心**：  
> 所有指标均为**可观测行为数据**，非心理特质评判；  
> 公式输出的是"做了什么"的量化结果，不是"是什么样的人"的定性标签  
>  
> 💡 **应用核心**：  
> 用工程数据衡量产出（L5），用解决方案质量衡量思维（L2），用成长动作衡量潜力（L1）——  
> 既尊重后端工作的专业性，又保留对人的理解温度

---

> 📎 **附：快速验算模板**
> ```
> 输入：L5=__ L4=__ L3=__ L2=__ L1=__  C=__  B₊=__  B₋=__
> 
> 加权基础分 = L5×C×0.5 + L4×0.2 + L3×0.15 + L2×0.1 + L1×0.05
> 最终绩效分 = MAX(0, MIN(120, 加权基础分×10 + B₊ - B₋))
> 评级 = IF(≥105,"S",IF(≥90,"A",IF(≥75,"B",IF(≥60,"C","D"))))
> ```
